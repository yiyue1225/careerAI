# 系统技术架构说明

## 整体架构概览

CareerAI 采用经典的前后端分离 + AI编排层的多层架构，共分为5层：

```
┌──────────────────────────────────────────────────────────────┐
│  表现层 Presentation Layer                                   │
│  Vue 3 + TypeScript | Element Plus | ECharts 6.0 | Vite     │
│  页面：首页 / 岗位画像库 / 能力画像 / 职业匹配 / 志愿填报    │
│        AI智能助手 / 管理后台                                 │
└────────────────────────┬─────────────────────────────────────┘
                         │ HTTP / Axios RESTful API
┌────────────────────────▼─────────────────────────────────────┐
│  业务逻辑层 Business Logic Layer                             │
│  Node.js + Express 5.2                                       │
│  ├── 岗位筛选与分页（buildWhereClause）                      │
│  ├── 人岗匹配算法（7维度差距计算）                           │
│  ├── 志愿分档计算（冲50-69% / 稳70-84% / 保85%+）           │
│  ├── 文件解析（pdf-parse / mammoth）                         │
│  ├── AI请求代理（统一转发 Dify API）                        │
│  └── 统计分析接口（行业分布 / 薪资排行 / 技能热度）         │
└──────────────┬──────────────────────────┬────────────────────┘
               │ mysql2                    │ HTTP/axios
┌──────────────▼────────┐  ┌──────────────▼────────────────────┐
│  数据访问层 DAL        │  │  AI 编排层 AI Orchestration       │
│  MySQL 8.0            │  │  Dify Platform (自托管)            │
│  连接池: 10并发        │  │  ├── 简历分析 Workflow             │
│  JSON字段: JSON_TABLE  │  │  │   输入: resume_text            │
│                       │  │  │   输出: 结构化JSON画像          │
│                       │  │  └── 职业规划 Chatbot              │
│                       │  │      维护 conversation_id         │
└──────────────┬────────┘  └──────────────┬────────────────────┘
               │                           │
┌──────────────▼────────┐  ┌──────────────▼────────────────────┐
│  数据层 Data Layer    │  │  模型层 Model Layer               │
│  10,000+ 岗位记录     │  │  Qwen-Turbo / GLM-4.5-Flash       │
│  8张业务表            │  │  via Dify API                     │
└───────────────────────┘  └───────────────────────────────────┘
```

## 各层职责详解

### 1. 表现层（前端）

| 技术 | 职责 |
|------|------|
| Vue 3 Composition API | 响应式数据绑定、组件化开发 |
| TypeScript | 类型安全，减少运行时错误 |
| Element Plus | 统一UI组件库（表单/表格/弹窗/步骤条） |
| ECharts 6.0 | 雷达图/饼图/柱状图/折线图可视化 |
| Pinia 3.0 | 跨组件状态共享（studentProfile全局存储） |
| Vue Router 5.0 | 客户端路由（7个主页面） |
| Vite | 构建工具，开发热更新 |

**核心组件**：
- `RadarChart.vue`：多色系列雷达图（复用于能力画像/匹配分析/管理后台）
- `Layout.vue`：侧边栏导航布局

### 2. 业务逻辑层（后端）

**核心算法 — 人岗匹配度计算**：
```
匹配度 = 100 - (Σ|学生维度i - 岗位维度i| / 7)
7个维度：专业技能、证书、创新能力、学习能力、抗压能力、沟通能力、实习经验
```

**志愿分档规则**：
- 冲一冲：匹配度 50-69%（挑战型）
- 稳一稳：匹配度 70-84%（匹配型）
- 保一保：匹配度 85%+（保底型）

**API接口列表**：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/positions | 岗位列表（分页+筛选） |
| GET | /api/position-filters | 行业/城市筛选项 |
| GET | /api/industry-stats | 行业分布统计 |
| GET | /api/stats | 平台总体统计 |
| GET | /api/skill-stats | 技能热度排行 |
| GET | /api/top-salary | 薪资最高职位排行 |
| POST | /api/analyze | 简历分析（接 Dify Workflow） |
| POST | /api/chat | AI助手对话（接 Dify Chatbot） |

### 3. 数据访问层

**主表结构 — job_standard_profile**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键 |
| job_name | VARCHAR | 岗位名称 |
| company_name | VARCHAR | 公司名称 |
| city | VARCHAR | 城市 |
| salary | VARCHAR | 薪资（如"15-25K"） |
| industry | TEXT | 原始行业描述 |
| clean_industry | JSON | 标准化行业标签数组 |
| requirements | JSON | 技能要求（professionalSkills数组等） |
| dimensions | JSON | 7维度得分（0-100） |

**JSON字段说明**：
```json
{
  "requirements": {
    "professionalSkills": ["Java", "Spring Boot", "MySQL"],
    "certificates": ["软考"],
    "innovation": 70,
    "learning": 80
  },
  "dimensions": {
    "professional": 75,
    "certificate": 60,
    "innovation": 65,
    "learning": 80,
    "stress": 70,
    "communication": 75,
    "internship": 50
  }
}
```

### 4. AI 编排层

**简历分析 Workflow**：
- 输入：`resume_text`（PDF/Word提取的纯文本）
- 处理：LLM解析简历，提取技能、经历、证书等
- 输出：标准化JSON画像（与dimensions/skills结构匹配）
- 端点：`POST /v1/workflows/run`

**职业规划 Chatbot**：
- 维护`conversation_id`实现多轮对话
- 系统提示：职业规划专家角色
- 端点：`POST /v1/chat-messages`

### 5. 数据层

来源：公开招聘平台数据清洗 + AI结构化标注
- 原始数据：`database/raw_data.csv`
- 处理：通过 Dify Workflow (DIFY_API_KEY_EXTRACT_INDUSTRY / DIFY_API_KEY_EXTRACT_JOB_INFO) 进行AI标注
- 最终：10,000+ 条标准化岗位记录

## 数据流向

```
用户上传简历
    ↓
Frontend(Profile.vue) 
    → POST /api/analyze (FormData)
    ↓
Backend 用 pdf-parse/mammoth 提取文本
    → POST {DIFY_API_URL}/workflows/run
    ↓
Dify Workflow (LLM解析)
    → 返回JSON画像
    ↓
Backend 解析JSON → 返回给前端
    ↓
Frontend 存入 Pinia store (studentProfile)
    ↓
Profile.vue 展示雷达图
PositionLibrary.vue 自动计算匹配度
Volunteer.vue 自动分档推荐
MatchReport.vue 详细匹配分析
```

## 技术选型原因

| 选型 | 原因 |
|------|------|
| Vue 3 + TypeScript | 组件化开发效率高，TypeScript提升代码质量 |
| Element Plus | 开箱即用的企业级组件，减少UI开发时间 |
| ECharts 6.0 | 丰富的图表类型，雷达图支持多系列多色 |
| Node.js + Express | 轻量快速，JavaScript全栈减少学习成本 |
| MySQL 8.0 | JSON_TABLE支持，可以高效查询JSON字段 |
| Dify (替代RAGFlow) | 内存占用更小（RAGFlow在2C/4G下OOM），可视化Workflow编排 |
| Pinia | Vue3官方推荐状态管理，轻量简洁 |
| html2pdf.js | 浏览器端PDF导出，无需服务器渲染 |

## 架构总览

### 系统宏观视图

```
┌────────────────────────────────────────────────────────────┐
│                    用户端 (Web Browser)                     │
│                    Vue3 + TypeScript                        │
└────────────────────┬─────────────────────────────────────┘
                     │ HTTP/HTTPS + REST API
                     │ Axios (JSON格式)
                     │
┌────────────────────▼──────────────────────────────────────┐
│        API网关与应用服务层 (Express.js)                    │
│        ├─ CORS处理                                         │
│        ├─ 路由分配                                         │
│        ├─ 请求验证                                         │
│        ├─ 文件上传处理 (Multer)                            │
│        └─ 认证中间件 (Bearer Token)                        │
└────────┬──────────────────────────┬──────────────────────┘
         │                          │
    ┌────▼────────┐         ┌───────▼───────────┐
    │  数据库层   │         │  AI服务层        │
    │  MySQL 8.0  │         │  Dify Platform   │
    │  + 连接池   │         │  + LLM模型       │
    │  (10,000+  │         │                   │
    │   岗位记录) │         │  ├─ 简历解析    │
    └────────────┘         │  └─ 对话助手    │
                           └───────────────────┘
```

### 核心特征

- **前后分离**：前端Vue3，后端Node.js，通过REST API通信
- **异步非阻塞**：AI服务采用SSE流式传输，不等待完整响应
- **数据驱动**：所有推荐决策基于算法而非硬编码规则
- **模块化设计**：各层职责清晰，便于独立开发和扩展
- **容错机制**：AI服务失败时自动降级到本地规则

## 五层分布式架构详解

### 第1层：表现层 (Presentation Layer)

**技术栈**：Vue3 + TypeScript + Element Plus + ECharts + Vite

**职责**：
- 渲染用户界面
- 收集用户输入
- 实时显示数据和反馈

**核心组件**：

1. **路由管理** (`src/router/index.ts`)
   - 9个主路由：Home, Profile, PositionLibrary, PositionDetail, MatchReport, Volunteer, AIAssistant, Admin, Login
   - 路由守卫：Admin路由需Bearer token认证
   - 元数据：`noLayout`标记（Login页面无侧边栏）

2. **状态管理** (`src/store/index.ts` - Pinia)
   - `studentProfile`：学生能力画像（7维+技能）
   - `targetPositionId`：岗位库导航的目标岗位
   - 跨页面共享，持久化存储

3. **UI组件库** (Element Plus + ECharts)
   - 自动导入：无需手动import
   - 雷达图：支持多系列对比
   - 表格、分页、日期选择等标准组件

4. **业务组件** (`src/components/`)
   - `Layout.vue`：主框架（侧边栏+内容区）
   - `RadarChart.vue`：多系列雷达图
   - `PositionAnalysis.vue`：岗位分析面板（可复用）

**数据流**：
```
用户交互 → 事件处理 → Axios发起请求 → API响应 → 状态更新 → 视图重新渲染
```

**性能特性**：
- Vite热更新：<100ms重编译
- Tree shaking：剔除未使用代码
- Code splitting：按路由分片加载
- 懒加载：路由级别动态import

   ```javascript
   // 连接池配置
   ```

5. **错误处理**
   ```
   try-catch → 区分业务错误vs系统错误 → 返回结构化错误响应
   ```

### 第3层：数据访问层 (Data Access Layer)

**技术栈**：MySQL 8.0 + mysql2/promise 驱动

**职责**：
- 接收查询请求
- 执行SQL语句
- 返回数据结果

**核心表设计**：

1. **job_standard_profile** (岗位主表)
   ```sql
   id (PK)
   job_name (INDEX)
   company (INDEX)
   location
   salary
   industry (INDEX)
   clean_industry (INDEX for JSON_CONTAINS)
   dimensions (JSON) → {professional, certificate, ...}
   requirements (JSON) → {professionalSkills[], education, ...}
   created_at, updated_at
   ```

2. **student_profile** (学生画像)
   ```sql
   id (PK)
   user_id (UNIQUE INDEX)
   dimensions (JSON) → {professional, certificate, ...}
   skills (JSON) → {professionalSkills[], softSkills[]}
   resume_text (TEXT)
   source ('ai' | 'fallback')
   created_at, updated_at
   ```

3. **wishlist** (志愿清单)
   ```sql
   id (PK)
   user_id (INDEX)
   positions_json (JSON) → [{positionId, tier, rank}]
   report_pdf (LONGBLOB)
   created_at, updated_at
   ```

4. 其他表（industry_dict, city_dict, certificate_dict, growth_path_rules）

**查询优化**：
- JSON字段使用 `JSON_CONTAINS()` 快速过滤
- 关键字段建立索引（job_name, industry, city）
- 分页使用LIMIT+OFFSET，大数据量可用游标
- 连接池减少连接开销

**关键SQL语句**：

```sql
-- 1. 多条件搜索岗位
SELECT * FROM job_standard_profile
WHERE (job_name LIKE ? OR company LIKE ?)
  AND JSON_CONTAINS(requirements->'$.professionalSkills', JSON_QUOTE(?))
  AND location = ?
  AND JSON_CONTAINS(clean_industry, JSON_QUOTE(?))
ORDER BY id
LIMIT 8 OFFSET 0;

-- 2. 行业分布（用于饼图）
SELECT clean_industry as name, COUNT(*) as value
FROM job_standard_profile
GROUP BY clean_industry
ORDER BY value DESC
LIMIT 10;

-- 3. 薪资TOP8（用于柱图）
SELECT job_name,
  AVG(CAST(REPLACE(REPLACE(salary, 'k', '000'), '万', '10000') AS UNSIGNED)) as avg_salary
FROM job_standard_profile
WHERE salary IS NOT NULL AND salary != ''
GROUP BY job_name
ORDER BY avg_salary DESC
LIMIT 8;

-- 4. 技能热度TOP60
SELECT professionalSkills, COUNT(*) as frequency
FROM job_standard_profile, JSON_TABLE(
  requirements->'$.professionalSkills',
  '$[*]' COLUMNS (professionalSkills VARCHAR(255) PATH '$')
) AS jt
GROUP BY professionalSkills
ORDER BY frequency DESC
LIMIT 60;
```

### 第4层：AI编排层 (AI Orchestration Layer)

**技术栈**：Dify Open-Source Platform + LLM(Qwen/GLM)

**职责**：
- 管理大语言模型的调用
- 编排复杂的AI工作流
- 维护多轮对话上下文

**核心特性**：

1. **两个独立的Agent应用**

   **简历解析Agent**：
   ```
   输入：resume_text (简历文本，≤4000字符)
   处理：
     - 分析职位、经历、技能、学位
     - 评估7维能力水平
     - 提取核心技能标签
   输出：JSON格式的能力画像
   {
     "dimensions": {
       "professional": 75,
       "certificate": 60,
       ...
     },
     "skills": {
       "professionalSkills": ["Java", "Spring", ...],
       "softSkills": [...]
     }
   }
   ```

   **智能对话Agent**：
   ```
   输入：message (用户问题)，conversation_id (可选，维持上下文)
   处理：
     - 理解用户意图
     - 基于职业规划知识库回答
     - 提供具体建议和行动方案
   输出：Markdown格式的回复文本
   ```

2. **流式传输 (SSE)**
   ```
   设置：response_mode = 'streaming'
   格式：Server-Sent Events (SSE)
   
   事件流：
   data: {"event":"agent_message","answer":"第一部分...","id":"..."}
   data: {"event":"agent_message","answer":"第二部分...","id":"..."}
   ...
   
   前端/后端按需收集answer deltas，拼接完整回复
   ```

3. **对话上下文管理**
   ```
   conversation_id：Dify自动维护
   
   用户→提问1→AI→回复1（返回conversation_id）
                    ↓
   用户→提问2→+conversation_id→AI→回复2（含前文上下文）
   
   支持长期对话，无需重复背景介绍
   ```

4. **容错降级**
   ```
   尝试：调用Dify Agent
   失败→捕获异常→执行本地规则（buildMockProfile）→返回降级结果
   
   降级结果包含source标记，前端可提示用户
   ```

**与后端的集成**：
```javascript
// 后端调用Dify
const response = await axios.post(
  DIFY_API_URL + '/chat-messages',
  {
    inputs: { resume_text: resumeText },
    response_mode: 'streaming'
  },
  { 
    headers: { Authorization: `Bearer ${DIFY_API_KEY}` },
    responseType: 'stream'  // 关键：接收流
  }
)

// 后端解析SSE流并转发给前端
response.data.on('data', (chunk) => {
  const lines = chunk.toString().split('\n')
  lines.forEach(line => {
    if (line.startsWith('data:')) {
      const json = JSON.parse(line.slice(5))
      if (json.event === 'agent_message') {
        fullAnswer += json.answer  // 累加delta
      }
    }
  })
})
```

## 关键组件设计

### 1. 匹配度算法组件

**设计目标**：将学生和岗位在多维度上进行科学的匹配评分

**核心算法**：相对缺陷模型
```
相对缺陷 = (岗位要求 - 学生分数) / 岗位要求

匹配度 = 100 * (1 - 平均相对缺陷)
       = 100 * (1 - sum(各维度相对缺陷) / 维度数)
```

**实现代码**：
```typescript
export const calcMatchScore = (
  studentDims: Record<string, number>,
  jobDims: Record<string, number>
): number => {
  const dims = ['professional', 'certificate', 'innovation', 'learning', 'stress', 'communication', 'internship']
  
  const deficits = dims.map(d => {
    const studentScore = studentDims[d] || 0
    const jobRequirement = jobDims[d] || 0
    const gap = Math.max(0, jobRequirement - studentScore)
    return gap / Math.max(1, jobRequirement)  // 相对化
  })
  
  const avgDeficit = deficits.reduce((a, b) => a + b) / dims.length
  return Math.max(0, Math.min(100, Math.round(100 * (1 - avgDeficit))))
}
```

**优势**：
- ✓ 相对评分，考虑岗位本身的难度水平
- ✓ 分数分布合理（50-95%），区分度高
- ✓ 用户易于理解（缺陷相对化后更直观）
- ✓ 支持动态调整权重（未来）

**示例**：
```
学生：professional=75, certificate=60, ...（其他维度平均70）
岗位A（简单）：professional=80, certificate=40, ...（其他维度平均50）
  → 相对缺陷都很小 → 匹配度=92%（高分，因为岗位要求低）

岗位B（复杂）：professional=90, certificate=80, ...（其他维度平均85）
  → 相对缺陷都较大 → 匹配度=68%（低分，因为岗位要求高）
```

### 2. 简历解析管道

**设计目标**：从上传的简历文件中提取结构化的能力画像

**处理流程**：
```
文件上传(PDF/Word/Text)
  ↓
文件类型检测
  ├─ PDF → pdf-parse提取文本
  ├─ Word → mammoth提取文本
  └─ Text → 直接读取
  ↓
文本预处理（截断到4000字符）
  ↓
调用Dify简历解析Agent（流式）
  ├─ 成功 → 解析JSON响应
  └─ 失败 → 本地规则降级(buildMockProfile)
  ↓
返回能力画像 {dimensions, skills, source}
```

**容错机制**：
```javascript
try {
  // 尝试Dify调用
  const difyResult = await callDifyAgent(resumeText)
  const parsed = extractJSON(difyResult)
  return { ...parsed, source: 'ai' }
} catch (err) {
  // 降级到本地规则
  const localResult = buildMockProfile(resumeText)
  return { ...localResult, source: 'fallback' }
}
```

**前端反馈**：
- `source: 'ai'`显示标记，增加用户信任
- `source: 'fallback'`显示提示，鼓励重试或手动调整

### 3. 多轮对话管理

**设计目标**：支持长期连续的职业咨询，保持上下文理解

**核心机制**：

1. **对话初始化**
   ```typescript
   const response = await fetch('/api/chat', {
     method: 'POST',
     body: JSON.stringify({
       message: '我是应届生，专业是计算机科学',
       // conversationId 缺失，自动生成新对话
     })
   })
   
   const { answer, conversationId } = await response.json()
   // 保存 conversationId
   ```

2. **对话持续**
   ```typescript
   const response2 = await fetch('/api/chat', {
     method: 'POST',
     body: JSON.stringify({
       message: '那么对于我的情况，Java工程师是否合适？',
       conversationId: savedId  // 传递前次对话ID
     })
   })
   // Dify自动加载历史，理解"我"的背景
   ```

3. **Dify的上下文窗口**
   - 默认保持最近10轮对话
   - 每次请求带上conversation_id
   - Agent自动管理历史的压缩和摘要

**前端实现**（`AIAssistant.vue`）：
```typescript
const conversationId = ref('')

const sendMessage = async () => {
  const response = await fetch('/api/chat', {
    method: 'POST',
    body: JSON.stringify({

  const data = await response.json()
```

### 4. 权限认证系统

**设计目标**：保护admin路由，防止未授权访问

**认证流程**：

1. **登录阶段** (`/api/admin/login`)
   ```javascript
   POST /api/admin/login
   Body: { username: "admin", password: "admin123" }
   Response: { code: 0, token: "base64编码的token" }
   ```

2. **Token存储**
   ```typescript
   // 前端
   const token = response.data.token
   localStorage.setItem('adminToken', token)
   ```

3. **路由守卫** (`src/router/index.ts`)
   ```typescript
   router.beforeEach((to, from, next) => {
     if (to.path.startsWith('/admin') && to.path !== '/admin/login') {
       const token = localStorage.getItem('adminToken')
       if (!token) {
         next('/admin/login')  // 重定向登录
       } else {
         next()
       }
     } else {
       next()
     }
   })
   ```

4. **API认证** (后端)
   ```javascript
   const authMiddleware = (req, res, next) => {
     const authHeader = req.headers.authorization
     if (!authHeader || !authHeader.startsWith('Bearer ')) {
       return res.status(401).json({ code: 1, message: '未授权' })
     }
     // 验证token的有效性
     next()
   }
   
   // 在受保护的路由前应用
   app.get('/api/admin/positions', authMiddleware, handler)
   ```

**特点**：
- 简化的固定凭证（适合竞赛）
- 不涉及数据库查询
- 前后端配合的二次验证

## 数据流和交互设计

### 1. 简历解析流程

```
用户上传简历 (Profile.vue)
  │
  ├─ 前端验证：文件大小、格式
  │
  ├─ 发送 POST /api/analyze
  │   Body: multipart {file, conversationId?}
  │
  └─ 后端处理
     ├─ 读取文件内容
     ├─ 调用Dify Agent
     ├─ 接收流式响应
     ├─ 拼接完整答案
     └─ 返回 {dimensions, skills, source}
        │
        ├─ 前端展示结果
        ├─ 保存到Pinia store (studentProfile)
        └─ 显示source标记
```

**关键变量传递**：
```
前端 → 后端：简历文本（通过FormData）
后端 → Dify：resume_text 变量（在Agent中使用）
Dify → 后端：JSON格式的能力画像
后端 → 前端：结构化的response + source标记
```

---

### 2. 岗位搜索和匹配流程

```
用户输入搜索条件 (PositionLibrary/MatchReport)
  │
  ├─ 前端发送 GET /api/positions?keyword=&skill=&city=...
  │
  └─ 后端处理
     ├─ buildWhereClause() → SQL条件
     ├─ 执行查询（分页）
     ├─ 返回 {data: [...], total, page}
        │
        ├─ 前端计算匹配度 (calcMatchScore)
        ├─ 按匹配度排序
        └─ 分档展示（冲/稳/保）
```

**数据计算位置**：
- **后端**：数据库查询、分页、WHERE条件构建
- **前端**：匹配度计算、排序、分档、可视化

**设计理由**：
- 后端专注数据获取，前端专注展示
- 减少网络传输（不需要传送已计算的匹配度）
- 用户能实时看到排序变化（修改参数后立即重新计算）

### 3. AI对话流程

```
用户发送消息 (AIAssistant.vue)
  │
  ├─ 前端显示消息到chat history
  ├─ 发送 POST /api/chat
  │   Body: {message, conversationId}
  │
  └─ 后端处理
     ├─ 调用Dify Agent（流式模式）
     ├─ 解析SSE事件流
     ├─ 累加answer deltas
     ├─ 关闭流
     └─ 返回 {answer, conversationId}
        │
        ├─ 前端接收响应
        ├─ 保存conversationId
        ├─ 将AI回复添加到历史
        ├─ 渲染Markdown（支持代码块、列表等）
        └─ 自动滚动到最新消息
```

**流式传输优势**：

## 总结

CareerAI的系统架构设计遵循以下原则：

1. **分层清晰**：表现层、业务层、数据访问层、AI层、数据层各司其职
2. **前后分离**：独立迭代，接口稳定
3. **算法驱动**：相对缺陷匹配算法确保科学性
4. **容错有备**：AI不可用时本地规则自动降级
5. **性能优化**：流式传输、数据库优化、缓存策略
6. **安全第一**：输入验证、参数化查询、权限控制
7. **易于扩展**：模块化设计，支持功能升级和架构演进

这个架构既支持当前的功能需求，也为未来的规模增长和功能扩展预留了充足的空间。

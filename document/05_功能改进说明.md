## 改进概述

针对用户反馈的3个主要问题进行了改进：

## 改进详情

### 1️⃣ **简历上传的统一管理**

#### 问题
- 用户在"我的能力"模块上传简历解析后，无法在"AI智能助手"中直接使用
- 两个模块的上传功能完全独立，不能共享数据

#### 解决方案
**在AIAssistant.vue中集成简历解析功能**：

```typescript
// 当用户在AI助手中上传文件时：
1. 调用 /api/analyze 进行简历解析（与Profile.vue相同逻辑）
2. 将解析结果自动保存到 Pinia 的 userStore.studentProfile
3. 显示解析成功提示
4. 同步到"我的能力画像"页面
```

#### 具体改动

**文件**：`src/views/AIAssistant.vue`

**新增逻辑**：
```typescript
// 导入 Pinia store
import { useUserStore } from '@/store'
const userStore = useUserStore()

// 发送消息前检查是否有文件
const sendMessage = async () => {
  if (file) {
    // 第一步：解析简历（调用 /api/analyze）
    const analyzeRes = await fetch('/api/analyze', { method: 'POST', body: formData })
    
    // 第二步：保存到全局状态
    userStore.setStudentProfile({
      dimensions: analyzeData.data.dimensions,
      skills: analyzeData.data.skills,
      source: analyzeData.data.source
    })
    
    // 第三步：提示用户已同步
    ElMessage.success('✓ 简历解析完成，已保存到「我的能力画像」')
  }
}
```

#### 用户体验改进
- 附件提示改为：✓ 发送后将自动解析并保存到「我的能力画像」
- 解析完成后显示成功提示和建议
- 自动同步到Profile页面，无需重复上传

### 2️⃣ **岗位关联图谱数据完善**

#### 问题
- RelationGraph组件显示的节点和链接都是"未知"
- 图谱对用户没有实际参考价值

#### 解决方案
**添加默认职业关系数据**：

```typescript
// 当没有传入真实数据时，使用默认的职业发展路径
const nodes = [
  { name: '初级工程师', category: '初级', value: 10 },
  { name: '高级工程师', category: '中级', value: 20 },
  { name: '技术专家', category: '高级', value: 30 },
  { name: '技术主管', category: '管理', value: 25 },
  { name: '产品经理', category: '换岗', value: 20 },
  { name: '架构师', category: '高级', value: 30 },
]

const links = [
  { source: '初级工程师', target: '高级工程师', type: 'promotion' },
  { source: '高级工程师', target: '技术专家', type: 'promotion' },
  { source: '高级工程师', target: '技术主管', type: 'promotion' },
  { source: '技术专家', target: '架构师', type: 'promotion' },
  { source: '高级工程师', target: '产品经理', type: 'transform' },
  { source: '技术主管', target: '产品经理', type: 'transform' },
]
```

#### 具体改动

**文件**：`src/components/RelationGraph.vue`

**改进内容**：
```typescript
function updateGraph() {
  // 如果没有传入数据，使用默认的职业关系
  const nodes = props.nodes && props.nodes.length > 0 ? props.nodes : [默认数据]
  const links = props.links && props.links.length > 0 ? props.links : [默认链接]
  
  // 增强标签显示
  label: { show: true, position: 'bottom', fontSize: 12 }
  edgeLabel: { 
    fontSize: 11, 
    distance: 5,
    formatter: link.type === 'promotion' ? '晋升路径' : '转换方向'
  }
}
```

#### 效果
- 图谱现在显示真实的职业发展路径
- 包含晋升路径和转换方向两种关系
- 支持自定义数据（如果传入真实数据会覆盖默认值）

### 3️⃣ **雷达图的大小和标签优化**

#### 问题一：雷达图太小
- 容器最小高度仅300px，导致图表较小
- 维度数值难以清晰查看

#### 解决方案
**增加容器最小高度到450px**：

```typescript
// 修改前
<div ref="chartRef" style="width: 100%; height: 100%; min-height: 300px"></div>

// 修改后
<div ref="chartRef" style="width: 100%; height: 100%; min-height: 450px"></div>
```

#### 问题二：雷达图上没有分数显示
- 维度分数只在悬停时显示
- 用户无法直观看到各维度的具体数值

#### 解决方案
**在雷达图series配置中添加label显示**：

```typescript
label: {
  show: true,                  // 始终显示标签
  color: p.color,             // 使用对应系列的颜色
  fontSize: 12,               // 适当的字体大小
  fontWeight: 'bold',         // 加粗便于阅读
  distance: 8,                // 与数据点的距离
  formatter: (params) => params.value[params.dimensionIndex] || 0  // 显示维度值
}
```

#### 具体改动

**文件**：`src/components/RadarChart.vue`

**改进内容**：

```typescript
series: allSeries.map((s: any, idx: number) => {
  const p = PALETTE[idx % PALETTE.length]
  return {
    name: s.name,
    type: 'radar',
    symbol: 'circle',
    symbolSize: 6,                    // 增加符号大小
    lineStyle: { color: p.color, width: 2 },
    itemStyle: { 
      color: p.color, 
      borderColor: '#fff',            // 添加白色边框
      borderWidth: 2 
    },
    label: {                          // 🆕 添加标签配置
      show: true,
      color: p.color,
      fontSize: 12,
      fontWeight: 'bold',
      distance: 8,
      formatter: (params) => params.value[params.dimensionIndex] || 0
    },
    areaStyle: {
      color: new echarts.graphic.RadialGradient(...)
    },
    data: [...]
  }
})
```

#### 效果
- 雷达图现在显示得更大（450px高度）
- 每个数据点旁边直接显示分数（如75、80等）
- 支持多系列对比时，每条线都有不同颜色的分数标签
- 悬停时仍然显示详细的tooltip信息
